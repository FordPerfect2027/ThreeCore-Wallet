# 3トークンの保存期間レポート

この画面では、PC内に保存したDAT・EMA・CAWELONの期間の控えを選び、
それぞれの開始残高・終了残高・Transfer履歴による差引を確認します。
今回の更新はPC内の開発版です。GitHubや公開サイトへの反映は行っていません。

## 使う場面

- 3トークンの同じ期間を、別々の公開アドレスで確認する。
- 取得途中の控えと取得済みの控えを見分ける。
- 終了残高とTransfer履歴の間に説明できない差がないか調べる。
- 確認した記録をJSONに保存し、後日同じ内容を開き直す。
- CSVで3トークンの要約を確認する。
- HTMLをブラウザーで開き、印刷用の報告を読む。
- 別の報告を開く前に、現在の報告と何が変わるか確認する。

このレポートは、保存済みの記録を読む機能です。
画面を開くだけでウォレットに接続したり、ブロックチェーンへ再取得を依頼したりしません。

## 作成手順

1. 先に期間取得画面で必要な記録を集め、期間の保存一覧に名前を付けて保存します。
2. 報告画面の「報告用に保存一覧を読み込む」を押します。
3. DAT・EMA・CAWELONで使用する控えをそれぞれ選びます。
4. 必要に応じて報告名を変更します。1〜60文字で指定できます。
5. 「選んだ記録で報告内容を確認」を押します。
6. アドレス、チェーン、開始・終了ブロック、取得状態を確認します。
7. 「確認した内容で報告を作成」を押します。

未選択のトークンは「記録が選ばれていません」と表示されます。
少なくとも1トークンを選ぶと報告を作成できますが、
3トークンが同じ条件でそろったとは表示しません。

同じトークンの複数の控えを自動統合することはありません。
名前が似ていても、アドレス、チェーン、対象期間を確認して選んでください。
非表示保管した記録も、状態を明示した上で選択できます。

## 表示の意味

各カードに、終了残高と「未説明の差」を表示します。
「残高・取得状態の内訳」を開くと、開始残高や取得工程も確認できます。

未説明の差は、次の計算です。

    終了残高 − 開始残高 − 履歴による差引

履歴による差引は、対象アドレスへの入金から出金を差し引いた値です。
同じアドレスから同じアドレスへの移動は、差引ゼロになります。
開始ブロックAの残高にはA内の取引が含まれるため、履歴の対象は(A, B]です。

値は整数の最小単位で計算します。
小さな差を丸めてゼロにはしません。
取得されていない値は「未取得」と表示し、ゼロと区別します。

| 表示 | 意味 |
| --- | --- |
| 保存された残高と履歴の計算が一致 | 保存した証拠からの算術計算が一致 |
| 取得途中 | 予定した取得工程が未完了 |
| 説明できない残高差あり | 保存した履歴だけでは残高差を説明できない |
| 履歴の途中残高に矛盾あり | 履歴の順序に沿った計算に矛盾がある |
| 再取得が必要 | 元の控えに再取得が必要という印が付いている |
| ブロック記録に不一致 | 同じチェーン・同じ番号のブロックのハッシュが一致しない |

別々のトークンの数量を合算して総資産額とは表示しません。
表示されるイベントの合計はトークン別件数の合計で、チェーン全体の一意な取引件数ではありません。

## 3トークン全体の状態

全体が一致と表示されるには、3つの記録が選択され、同じチェーン・同じ期間で、
すべて取得済みかつ計算が一致し、既知のブロック不一致や再取得の印がないことが必要です。

複数のトークンで同じ公開アドレスを使用している場合は、そのことを補足表示します。
同じアドレスであるだけで計算を失敗にはしませんが、独立した3つのウォレットであるとも扱いません。
取得時の区切りの大きさが違っても、開始・終了ブロックが同じなら期間は同一です。

## 履歴を調べる

「計算に使ったTransfer履歴を見る」を開きます。
トークンと入出金方向で絞り込み、アドレス、取引ハッシュ、ブロック番号を検索できます。
1ページ25件です。

絞り込みは表の表示だけに作用します。
上部カードの残高、差額、全体の状態を、検索結果だけで再計算することはありません。

## 報告を差し替える前の比較

すでに報告を表示しているときに別の報告JSONを開くと、反映前の確認欄に差が表示されます。

- 新しく追加されるトークン、選択から外れるトークン。
- 取得工程の増減。
- 保存した履歴の追加、除外、同じ取引に関する内容変更。
- 名前や保存情報だけの変更。
- アドレス、チェーン、対象期間の変更。
- ブロックハッシュの変更。
- 再取得が必要という印が付く場合、外れる場合。

同じアドレス・チェーン・期間で、既知のハッシュ不一致や再取得の印がない場合に限り、
記録間の終了残高差も最小単位で表示します。
これは過去の控えの記載内容の差であり、現在の入出金や利益の計算ではありません。

印が外れたJSONを受け取っても、その理由を認証するものではありません。
確認を中止すれば、現在表示している報告を維持します。
自動的な統合や、元の控えへの上書きは行いません。

## 保存形式

| 形式 | 用途 | 再読込み |
| --- | --- | --- |
| JSON | 選んだ控えの元データと報告名を保全 | 可能 |
| CSV | 3トークンの状態・残高・差額を一覧化 | 不可 |
| HTML | ブラウザーで読む・印刷する要約 | 不可 |

保存前に、公開アドレス・残高・履歴を含むことを確認するチェックを入れます。
これらのファイルは暗号化されていません。
秘密鍵やシードフレーズを入力する必要はありません。

JSONには計算結果を信頼済みの結論として入れず、元の記録を保存します。
開き直したときに検証と計算をやり直します。
SHA-256チェックサムは破損検出用で、作成者やブロックチェーンの正しさの証明ではありません。

HTMLはスクリプトや外部接続を含まない要約です。
CSVの数量は正確な最小単位の文字列です。
表計算ソフトで数値に変換すると大きな桁が丸められる場合があるため、文字列として読み込んでください。
マイナスや数式のような先頭文字は、数式として実行されないようアポストロフィを付けています。

## 開き直す

「保存した報告JSONを開く」でファイルを選び、内容を確認して反映します。
元の保存一覧が別のブラウザーにあった場合でも、JSON内の記録から報告を作成できます。
読込みだけでは期間の保存一覧に記録を追加しません。

報告画面には自動保存機能はありません。
画面を閉じる前に、必要な報告をJSONに保存してください。
作成済みの報告は固定した過去の記録なので、後から保存一覧が変わっても自動更新しません。
新しく作り直す場合は保存一覧を再読み込みしてください。

## コマンドで確認する場合

    npm run period-report:check -- report.json --json

3トークンが同じ条件で計算一致していることを必要とする場合:

    npm run period-report:check -- report.json --require-agreement

終了コード0はファイルが正常、2は正常なファイルだが指定した一致条件を満たさない状態です。
終了コード1は読込みまたは形式のエラーです。
コマンドの出力には、公開アドレスや残高そのものを含めません。
ファイルやブラウザーの保存内容を変更せず、ネットワークにも接続しません。

## プレビューと確認の範囲

ローカルサーバーを`--ui-test`付きで起動すると、
`/test/browser/period-report-demo/`で模擬データの画面を利用できます。
専用ボタンで5件の控えをプレビュー専用の保存領域へ追加できます。
実際の保存一覧とは別のデータベースです。

この画面での一致は、保存した残高と履歴の計算上の一致です。
現在のチェーンの再確認、すべての履歴の完全性、独立監査、
取引の実行、利益、運用可能なウォレットの完成を示すものではありません。
