# 報告履歴の使い方

DAT・EMA・CAWELONの期間レポートを、名前とメモを付けてPC内に残す機能です。
保存した時点の残高・取得履歴・確認結果を、後日同じ条件で読み直せます。
通常のウォレット画面では、期間レポートの下に表示されます。

## 保存先

データはブラウザーのIndexedDBに保存します。
同じブラウザーでも、URLのポート番号が違うと別の保存場所になります。
例えば `http://127.0.0.1:4195` と `http://127.0.0.1:4196` は別です。
画面が空でも、以前のポートの記録を削除したことにはなりません。

ブラウザーのデータ消去やPC故障に備えるには、バックアップJSONも保存してください。
ブラウザー内の保存だけで、Documentsフォルダーなどに自動保存されるわけではありません。
別のブラウザーやポートへ移す場合も、JSONを使います。

## 新しい報告を保存する

1. 上の期間レポート画面で、3トークンの控えを選んで確認・作成します。
2. 「PC内の報告履歴を読み込む」を押します。
3. 保存名、必要ならメモとタグを入力します。
4. 「表示中の期間レポートを保存する前に確認」を押します。
5. 保存対象のトークン・期間・状態を読み、「確認した内容を適用」を押します。

途中まで取得した報告も保存できます。完了した報告と区別して表示されます。
確認中に上のレポートが変わった場合は、古い確認内容のまま保存できません。
変更後の内容をもう一度確認してください。

保存できるのは、通常の一覧と非表示保管を合わせて12件、全体で64 MiBまでです。
非表示保管に移しても空き件数は増えません。この版には完全削除の操作がありません。

## 名前・メモ・タグを変更する

一覧から報告を選び、編集後に「選択した報告の名前・メモを更新」を押します。
変更されるのは整理用の情報だけです。報告に含まれる元の記録は変更しません。

| 項目 | 制限 |
| --- | --- |
| 保存名 | 1〜60文字 |
| メモ | 500文字以内 |
| タグ | 最大6個、各24文字以内 |
| タグの文字 | 英小文字・数字・ハイフン。先頭は英小文字か数字 |

タグはカンマで区切ります。例: `daily, reviewed`。
同じタグの重複は受け付けません。パスワードや秘密鍵は入力しないでください。

## 探す・保管する

通常／非表示保管、確認状態、トークン、タグ、保存名やメモなどで絞り込めます。
「保存が新しい順」はPC内に保存した日時の順です。報告作成日時とは別です。
絞り込みによって選択中の報告が対象外になっても、別の報告へ勝手に切り替えません。

「非表示保管へ移す」で通常の一覧から外せます。
「保管状態」を変更して選び、「通常の一覧に戻す」で戻せます。
保管中の記録もバックアップと比較の対象です。

## 保存した報告を開く

1. 報告を選び、「この報告を開く前に確認」を押します。
2. 現在の表示との差と保存名を確認し、「確認した内容を適用」を押します。
3. 上の期間レポートに候補が表示されます。
4. そこで内容を確認し、「確認した内容で報告を作成」を押します。

確認前に現在の表示を置き換えません。
別タブで記録が変わっていた場合は、履歴を読み直してから再操作してください。

## 二つの報告を比較する

比較先を一覧で選び、「保存した2つの報告を比較」を開きます。
比較元を選んで、違いを表示します。

チェーン・アドレス・取得期間・ブロックハッシュ・取得工程・保存イベントなどを比較します。
さらに、期間の空白や重複、隣接する期間の境界の残高とハッシュを確認します。
期間は開始ブロックの翌ブロックから終了ブロックまでを扱います。
同じ期間の二つの報告は、連続した別期間として数えません。

これは保存された証拠同士の比較です。現在のブロックチェーンへの再照会はしません。
異なるトークンの数量を足したり、残高差を利益として表示したりはしません。

## 元の期間の控えと照合する

「元の期間の控えと照合」を押すと、現在PC内にある取得記録の一覧と比較します。
同じ控えが残っているか、メモだけ変わったか、元の証拠が変わったかなどを確認できます。
同じ内容が別番号で見つかった場合も、候補として表示するだけです。
報告の元データを差し替えたり、保存一覧の内容を書き換えたりしません。

## ファイルへの保存と復元

内容をPCに保存する確認欄にチェックを入れてから書き出します。

| ボタン | 内容 | 再読込み先 |
| --- | --- | --- |
| 全報告のバックアップJSON | 全件の報告・メモ・タグ・保管状態 | 報告履歴 |
| 選択した報告のJSON | 選択した報告の元記録。履歴のメモ等は含まない | 上の期間レポート |
| 絞り込んだ一覧CSV | 絞り込み後の一覧要約 | 閲覧用。復元用ではない |

バックアップには公開アドレス、残高、履歴、メモが含まれます。暗号化されていません。
チェックサムは破損の検出用であり、作者の認証や第三者監査ではありません。

復元は追加方式です。現在の報告をまとめて置き換える操作ではありません。
完全に同じ報告は重複登録せず、現在PC内にあるメモや保管状態を優先します。
同じ保存番号なのに報告内容が異なるものがあると、初期状態では適用できません。
競合の内容を確認したうえで、その競合だけ除外して他の新しい報告を追加できます。

重複判定には報告名と作成日時も含まれます。
同じ証拠でも報告名や作成日時が異なれば、別の報告として扱います。
読み込むJSONは96 MiBまで、復元後の履歴は12件・64 MiBまでです。

## 保存がうまくいかない場合

容量不足や別タブでの変更があれば、理由を表示して処理を止めます。
「履歴の処理を中止」は、すでに完了した保存を取り消す機能ではありません。
保存中に中止した場合は、読み込み直して実際の保存結果を確認してください。
既存記録を消して復旧する操作は行いません。

## PC内での確認用画面

`node examples/dev-server.js --ui-test` で起動したときだけ、
`/test/browser/report-history-demo/` に模擬記録を使った画面があります。
模擬画面の保存先は通常の履歴と別です。実ウォレットや外部サービスへ接続しません。
画面の「プレビュー用の模擬報告4件を用意」で記録を準備できます。

ファイルは次のコマンドでも確認できます。

```sh
npm run report-history:check -- ThreeCore-report-history.json --json
```

この検査はPC内のファイルだけを読み、残高を新たに取得しません。
