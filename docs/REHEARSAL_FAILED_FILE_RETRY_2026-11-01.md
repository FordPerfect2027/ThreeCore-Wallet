# Retry failed rehearsal report-file reviews

Item 547. Source: 03fbb57.

The rehearsal report batch now offers an explicit retry for read/hash failures after all initially selected files were attempted. It rereads and recomputes only those failed sources, retaining successful results and their source texts for the existing individual-detail action. Differences, failed expected outcomes, unsupported or invalid reports and external-checksum mismatches are not silently retried. The same original selection and optional reference are required; copied receipts and text-only batches cannot authorize a retry.

V5 JSON/CSV records bind the exact previous receipt by SHA-256 and expose zero-based target/completed/remaining indexes, sequence and retained-review count. Stop and timeout keep old failure rows for targets not retried. Retrying again only visits failures still present. Original results stay immutable, failed lineage hashing reads no source, and replacement or clearing revokes the pending UI result. The summary explicitly distinguishes old retained outcomes from new attempts. Existing V1–V4 output and continuation behavior remain compatible. Recomputations remain simulation-only and do not establish real execution, trusted origin or mainnet readiness.
