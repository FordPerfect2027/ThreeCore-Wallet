# ThreeCoreの接続・保存・復旧を確認する

この手順は、読み取り専用Walletと仮の記録による運用リハーサルのためのものです。
手順が書かれていることと、実機で確認が完了していることは別です。
最新の完了状況は[公開準備の確認表](RELEASE_READINESS_2026-11-01.md)に記録します。

## 作業中の画面を残す

入力や履歴があるタブは、確認用の新しい画面として使い回さないでください。
Walletと運用リハーサルの上部リンクは、相手の画面を別タブで開きます。
元のタブは残りますが、閉じる・再読み込みする前にはファイル保存が必要です。
同じページを別タブで開いても、元のタブの未保存データは自動で移りません。

同じPCでも、ChromeとMicrosoft Edgeではブラウザー内保存とWalletの接続許可が
別です。URLのポート番号が変わった場合も別の保存先になります。
開いているローカルサーバーを、別の版を試すために停止しないでください。
版の切り替えは[配布ファイルの確認と元の版への戻し方](SOURCE_CHECKPOINT_2026-11-01.md#preparing-and-returning-to-a-known-version)に従います。

操作接続が外れた場合は、担当者が同じサイトの運用リハーサルにある
「ThreeCore Walletを別タブで開く」を使い、新しい操作用タブで復旧できます。
元のタブを再読み込みする必要はありません。新しいタブには履歴が自動で
移らないため、保存済みファイルまたは同じURLのブラウザー内の控えを
プレビューして復元し、Walletの現在の許可済みアドレスを読み直します。

最新版の「開き方の確認」画面には、このサイト内のWalletまたはリハーサルを
開くリンクがあります。これを押して開ける場合、アドレスバーへの手入力は
不要です。以前から起動中のサーバーには、この案内変更が含まれない場合があります。

## 接続するアカウントをそろえる

再開時は、担当者が先に現在のカード、破損確認済みのバックアップ、保存履歴の
公開アドレスとチェーンを照合します。既に保存された公開アドレスを、操作を依頼した人へ
一式聞き直す必要はありません。次に下記の許可済みアドレス表示を使い、現在のWalletが
返す対象と照合します。保存記録は過去の対象を示すもので、現在の接続許可ではありません。
仮のSIM口座、トークンのコントラクトアドレス、同じ口座で確認した3トークンを、
異なる3つの実口座として数えないでください。保存記録と現在の表示だけでは不足する場合は、
不足している口座・割り当てだけを確認します。秘密鍵やシードフレーズは探しません。

1. DAT・EMA・CAWELONそれぞれについて、使う公開アドレスとチェーンを決めます。
   アカウント名の「Account 1」「Account 2」だけで判断せず、公開アドレスを確認します。
   同じ公開アドレスを複数のカードで使えます。新しい口座の作成は前提にしません。
   3カードの確認と、異なる口座への切り替え確認は分けて記録します。
   切り替えは既存のアカウント1・2を使えます。3つ目の口座がなくても開発を止めません。
   [現在の検証条件](SHARED_ACCOUNT_ACCEPTANCE_2026-11-02.md)に沿って、口座数とトークン数を区別します。
2. 対象カードの「接続するWallet」「このエージェントのWallet公開アドレス」
   「チェーン」を確認します。Base SepoliaのテストとBase Mainnetの読み取りを
   同じ記録として扱わないでください。
   既にこのサイトへの接続を許可している場合は「Walletの許可済みアドレスを確認」で
   公開アドレスとネットワークを表示できます。対象を確認し、「確認した公開アドレスを入力」
   を押すと、Walletの応答をもう一度照合して入力欄へ反映します。コピー・貼り付けは不要です。
   表示はWalletが最初に返したアドレスです。「Account 1」などの名前や所有権の証明では
   ありません。対象・ネットワークが違う場合は反映せず、設定を確認してください。
3. 「接続」を押し、Wallet自身の確認画面で接続先URLとアカウントを確認します。
   名前が合っていても、公開アドレスが違えば別の対象です。
4. ThreeCore側の接続表示を確認します。Walletの画面を開いただけでは完了しません。
   接続できた後に「公式アドレスを表示」で対象トークンとチェーンを確認し、
   「接続中のWalletで照合」など必要な読み取りだけを実行します。
5. 結果の対象アドレス、チェーン、トークン、ブロック、最小単位の残高を記録します。
   読み取り失敗・未確認は残高0ではありません。以前保存した結果の表示は、
   今回の接続や最新の残高の証明にはなりません。

MetaMaskなどでアカウントを切り替えると、他のカードの接続も無効になる場合が
あります。各カードの状態を確認し、過去の記録は保持したまま対象ごとに明示的に
接続し直してください。署名・送金・トークン承認取引は、この手順にはありません。

### MetaMaskで切り替えたのにThreeCoreへ反映されない場合

MetaMaskは接続サイトごとにネットワークを管理します。資産一覧で表示する
ネットワークや口座を変更しても、このサイトに許可された接続先まで変わったとは
限りません。ThreeCoreが読み取った公開アドレスとネットワークを基準に確認します。

2026年11月3日に確認したMicrosoft Edgeのサイドパネル表示では、下部に
`127.0.0.1:4233` と口座名があり、その右側の歯車のすぐ左にネットワークの
丸いアイコンと下向き矢印がありました。このボタンからBase Sepoliaを選ぶと、
ThreeCoreの3カードにネットワーク変更による停止が表示され、許可済みアドレスの
確認でもBase Sepoliaが返りました。同じ行の歯車から既存Account 2へ変更した際も、
3カードの口座変更による停止を確認しました。上方の「ネットワーク: Base Sepolia」は
資産一覧の表示です。この2つを区別し、版や表示形式が異なる場合は現在の画面で
対象サイトとボタンを確認してください。

1. ThreeCore Walletを開いている同じブラウザー・プロファイルでMetaMaskを開きます。
2. 右上の接続サイトのアイコンから、対象がこのThreeCoreのURLであることを確認します。
   カードの「この画面の接続先」と照合し、ポート番号も一致させます。
   `http://127.0.0.1:4231` と `http://127.0.0.1:4233` は別の接続先です。
   他のサイトの設定は変更しません。
3. サイトアイコンから開いた画面の**現在のネットワーク名**を押し、今回の対象を選びます。
   例えば現在がBaseなら、そのBase表示からBase Sepoliaを選びます。
   「権限を管理」のネットワーク一覧は、そのサイトに許可するネットワークの設定です。
   一覧へ追加しただけで現在のネットワークも切り替わったとは判断しません。
   Base SepoliaのチェーンIDは `84532`、Base Mainnetは `8453` です。
4. 口座も違う場合は、そのサイトの「権限を管理」または「Permissions」で
   接続する既存口座を確認対象に変更します。新しい口座を作る必要はありません。
5. 通常の接続確認では、ThreeCoreでカードのチェーンを今回の対象にそろえ、
   未接続のカードで「Walletの許可済みアドレスを確認」を押します。
   保護停止中なら先に「接続操作を再開する」を押します。接続済みでは確認ボタンは無効です。
   目的の公開アドレスとネットワークが表示された後に入力へ反映し、各カードで明示的に接続します。

**接続中の切り替えを検証するとき**は、先に保存ファイルを保全し、3カードが接続済みの
状態でMetaMask側を切り替えます。ThreeCoreの切断・設定変更・再開ボタンを押す前に、
各カードと保護履歴を記録してください。無操作や別画面への移動による停止が先に起きた場合、
その停止をネットワーク変更による停止として数えません。既定の保護は維持し、実際の
切り替えを観測できるときに接続し直して確認します。履歴の保全は別途、保存したJSONで照合します。

ネットワーク一覧にBase Sepoliaがない場合は、「テストネットワークを表示」を確認し、
未登録なら公式設定で追加します。RPCは `https://sepolia.base.org`、通貨記号は `ETH`、
エクスプローラーは `https://sepolia.basescan.org` です。
接続の変更と読み取り確認に、署名・送金・秘密鍵の入力は不要です。
表示やメニュー名はMetaMaskの版によって異なります。

参照: [MetaMaskのサイト別ネットワーク切替](https://support.metamask.io/configure/networks/how-to-change-networks)、
[サイト別の接続許可](https://support.metamask.io/more-web3/dapps/manage-dapp-permissions/)、
[テストネット表示](https://support.metamask.io/configure/networks/how-to-view-testnets-in-metamask)、
[Base公式設定](https://docs.base.org/get-started/connect-to-base)。

休憩前に「このブラウザーに控えを保存」で、対象が分かる名前の控えを残すと、
再読み込み後は「保存済みの控え一覧を読み込む」から選び直せます。
「選んだ控えの内容を確認」→「確認した控えを一括復元の入力欄へ」から、
下記の一括復元の変更確認へ進みます。復元後に接続するWalletを選び、明示的に
再接続してください。控えには接続許可を保存しません。ファイルも別に残してください。

| 表示・状況 | 次の操作 |
| --- | --- |
| アカウントが一致しない | Wallet側で意図した公開アドレスを選び直す。表示中の別口座に合わせるためだけにカードの設定を書き換えない |
| ネットワークが一致しない | Walletとカードのチェーンを、今回の確認対象にそろえてから再接続する |
| 許可画面がまだ処理中 | Walletに残っている確認を完了または取り消してから再接続する。「接続」を繰り返し押さない |
| 保護のため停止した | 「接続操作を再開する」の後、必要なカードで再接続する。過去の履歴はそのまま確認できる |
| ファイル選択を取り消した | 現在の履歴を確認してから選び直す。取り消しを保存完了として扱わない |

## Walletの履歴を保存し、別タブで戻す

1. 各カードで、必要な確認記録を「今回の確認結果を履歴に追加」など対応する
   保存履歴に追加します。「3ウォレットの保存状況を見る」で対象と件数を確認します。
2. 「3ウォレットの平文バックアップを保存」、または
   [合言葉付きバックアップ](ENCRYPTED_WORKSPACE_BACKUP_JA.md)で保存します。
   平文ファイルには公開アドレスと残高が含まれます。
3. ダウンロード先に実ファイルがあり、空でないことを確認します。
   「ダウンロードを開始しました」だけで保存完了と判断しないでください。
   元ファイルはそのまま保管します。
4. 空の確認用Walletタブを開き、「一括バックアップファイル」で保存したJSONを選びます。
   「設定とトークン一覧を復元する」「保存履歴を復元する」を確認し、
   「一括復元の変更内容を確認」を押します。
5. 対象・チェーン・件数・追加または置き換えの内容を確認します。
   意図した内容なら「変更する設定と履歴を確認しました」にチェックして
   「確認した内容を一括復元」を押します。
6. 保存前後で設定と履歴を比較します。復元後もWalletは未接続であることを確認し、
   新しい読み取りが必要な場合だけ接続します。
   選択した平文バックアップの破損確認が済んでいれば、
   「選んだファイルと現在の内容を照合」で設定・トークン一覧・保存履歴の一致を
   カードごとに確認できます。件数だけでなく、履歴の内容も照合します。
   既存履歴へ追加した場合は、以前の記録が残るため不一致になることがあります。
   このボタンは比較だけを行い、設定・履歴の変更や再接続は行いません。

この一括バックアップは、期間レポート・承認額・送受信履歴など別の保存一覧を
すべて含むものではありません。必要なコレクションは各欄から別にJSON保存します。
ファイル形式が分からない場合は「保存したJSONの種類と開く場所を調べる」を使います。
CSVは閲覧用です。復旧に使うJSONも残してください。

送受信履歴を「期間ごとの記録をまとめる」へ追加した後は、接続停止や接続設定の変更で
そのまとめが消えないことも確認します。途中の読み取りと未確定の確認画面は取り消されます。
別の口座・トークン・チェーンの記録を混ぜる操作は拒否され、以前のまとめは残ります。
「まとめたJSONを保存」は、接続先の入力が変わっても元の記録の内容で保存します。
画面の再読み込み・終了前には、このJSONを別に保存してください。
「この画面のまとめをクリア」は明示的な消去です。

## 運用リハーサルの履歴とケース集を戻す

1. 「履歴とケース集をまとめて保存」でJSONを保存し、実ファイルを確認します。
   保存対象は確定した履歴と比較ケースです。編集中の入力や検索条件は含みません。
2. 空の確認用リハーサルタブで「まとめた記録を選ぶ」を押し、そのJSONを選びます。
3. 変更内容を確認し、「確認した履歴とケース集をまとめて復旧」を押します。
   この操作は確認用タブの履歴とケース集を置き換えます。元の作業タブは残します。
4. DAT・EMA・CAWELONの確定記録数と、比較ケース数・内容を保存元と比較します。
   確認用タブから別名で保存し直せば、ファイル内容も照合できます。
5. 正しく戻せたことを確認してから、不要になった確認用タブだけを閉じます。

仮のSIM記録の復旧と、実ウォレットの残高履歴の復旧は別の確認です。
一方の成功だけで、もう一方の実機確認を完了扱いにはしません。

## 確認結果に残すこと

使用した開発版、ブラウザー、日時、対象・チェーン、保存前後の件数、保存ファイルの
照合値、確認できた操作と失敗した操作を残します。結果に実際のアドレスや残高を
含めて公開する場合は、公開対象を確認してください。秘密鍵やシードフレーズは
入力・記録・共有しません。

停止確認では、読み取り中に「3トークンの接続を停止」を押し、遅れて届いた応答で
結果が復活しないこと、保存済み履歴が残ること、再開後も明示的な再接続が必要なことを
確認します。できなかった操作は未確認のまま残します。
