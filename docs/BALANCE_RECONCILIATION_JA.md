# 残高と履歴の照合

DAT・EMA・CAWELONについて、保存した2時点の残高と、その間の送受信履歴を照合する機能です。
3トークンは別々のアカウント・チェーンで扱えます。
異なるトークンの金額を足し合わせることはありません。

## 今回できるようになったこと

- 比較前と比較後の残高記録を選ぶ。
- ウォレットカードの残高・送受信履歴を照合画面に取り込む。
- 過去に保存したトークン確認JSON、履歴JSON、履歴管理JSONを読み込む。
- 残高の増減と、履歴で説明できる増減を整数で比較する。
- 説明できない差額と、問い合わせていない期間を表示する。
- 同じイベントを含む重複した記録を1回だけ数える。
- ブロックごとの受取・送出・増減・推定残高を見る。
- 計算に使った元記録と、ブロックのハッシュを確認する。
- 照合データ全体をJSONに保存し、後から再開する。
- 結果、イベント、ブロック集計、未取得期間メモをCSVに保存する。

## 使い始める

通常のローカルウォレット画面に「残高と履歴の照合」が追加されています。
この欄で操作しても、ウォレットへの接続・署名・送金は発生しません。

最初は記録が入っていません。
各トークンのカードで取得した記録、または以前保存したファイルを使います。
現在の残高を新たに取得する場合は、従来どおりカード側の読み取り操作を使ってください。

### カードの記録を使う場合

1. 「照合に入れるトークン」でDAT、EMA、CAWELONを選びます。
2. カード側に比較前の残高記録を表示します。
3. 「カードの残高を比較前に入れる」を押します。
4. 確認欄でアカウント・チェーン・ブロック番号を見て、適用します。
5. カード側に比較後の残高記録を表示します。
6. 「カードの残高を比較後に入れる」を押し、同様に適用します。
7. カードに対象期間の送受信履歴を用意し、「カードの履歴を入れる」を押します。
8. 確認して適用した後、「現在の記録を照合する」を押します。

比較前と比較後を逆にすると、計算は行わず理由を表示します。
同じブロックの同じ残高を使った場合は、比較する期間は0ブロックです。

### ファイルを使う場合

「読み込むファイルの種類」で、保存ファイルに合う種類を選びます。
ファイルを選んだだけでは、照合中のデータは変更されません。
確認欄を読んでから適用してください。

| ファイルの種類 | 入る場所 |
| --- | --- |
| 照合データ全体 | 3トークンの前後の残高と履歴 |
| 比較前の残高 | 選択中トークンの比較前 |
| 比較後の残高 | 選択中トークンの比較後 |
| 送受信履歴アーカイブ | 選択中トークンの履歴 |
| 送受信履歴1期間 | 選択中トークンの履歴を1期間に置き換え |
| 3トークンの履歴管理JSON | 3トークンすべての履歴。前後の残高は維持 |

履歴管理JSONの空欄は、照合画面でも空欄になります。
そのため、既存履歴の削除になる場合は、確認欄に削除内容を表示します。

異なるトークンのファイルを、選択中トークンに入れることはできません。
別アカウントや別チェーンの記録は、残高と履歴の組み合わせを診断するために保持できます。
ただし、条件が一致するまで比較結果は出しません。

## 結果の読み方

| 表示 | 意味 |
| --- | --- |
| 残高の記録待ち | 比較前または比較後の記録がありません |
| 条件が合わず比較できません | アカウント、チェーン、順序、仕様、ハッシュなどに問題があります |
| 履歴の期間が不足しています | 比較区間の一部を問い合わせた記録がありません |
| 履歴の途中に矛盾があります | 途中の推定残高が負になるなど、記録に説明できない点があります |
| 保存した記録の計算が一致 | 記録の範囲に欠落がなく、差額が0で、計算上の矛盾を検出していません |
| 説明できない差額があります | 残高の変化と履歴の増減が一致していません |

「差額が0」と「履歴が十分」は別の確認です。
差額が0でも、途中の記録が欠けている場合は履歴不足として表示します。

金額は最小単位の整数で計算します。
小数点以下18桁の最小の差額も丸めて消しません。

### 自分宛の送信

自分のアドレスから同じアドレスに送った記録は、受取と送出の両方に入ります。
残高の増減は0です。
重複した取得結果を二重に数えることはありません。

### ブロックごとの履歴集計

比較前の残高に履歴の増減を加えて、途中残高を推定します。
各ブロックの残高を新たに読み取った値ではありません。
履歴に不足がある場合、その不足も一緒に表示します。

画面では先頭25ブロックを表示します。
全ブロックの集計は「ブロック集計をCSV保存」で保存できます。

### 未取得期間のメモ

不足している期間を、1回あたり最大2,000ブロックに分けて表示します。
一度に表示する読み取り候補は最大12期間です。
残りがある場合は、残りのブロック数を明記します。

このメモは読み取りを自動実行しません。
必要ならカード側で該当期間を読み取り、履歴に追加してから再度照合します。

## 保存して再開する

1. 「照合データを保存」を押します。
2. ブラウザーのダウンロード先にJSONがあることを確認します。
3. 次回は「照合データ全体」を選んで、そのJSONを読み込みます。
4. 確認欄を見て適用し、もう一度照合します。

照合データは自動でブラウザーに保存しません。
画面を閉じる前に、必要なデータをJSONで保存してください。
従来の履歴管理画面の保存記録を上書きすることもありません。

JSONには前後の残高、送受信記録、公開アドレス、ブロック番号、ハッシュが入ります。
秘密鍵、シードフレーズ、署名、送金権限は入りません。

CSVとテキストは、結果を読むためのファイルです。
照合画面へ復元するときはJSONを使ってください。
CSVは全トークン・全方向を出力し、画面上の検索フィルターは反映しません。
非常に長い整数を表計算ソフトで開く場合、数値化による丸めを避けるには列を文字列として読み込んでください。
負の値は、表計算ソフトの式として実行されないよう先頭にアポストロフィを付けています。

## 取り消しとデータの保全

- 取り込み前の確認は「取り込みを取り消す」で中止できます。
- すでに適用した変更は「元に戻す」で戻せます。
- 「やり直す」で戻した変更を再適用できます。
- 記録の置き換えや削除には確認チェックが必要です。
- 選択トークンやカードの内容が変わった場合、古い取り込み確認を適用できないようにします。
- 読み込み失敗や検査値の不一致で、現在の記録を消すことはありません。

元に戻せる履歴はメモリー内で最大8段階です。
大きなデータでは容量制限により少なくなる場合があります。
画面を閉じると取り消し履歴は消えます。長期保管にはJSONを使用してください。

## 模擬データのプレビュー

ローカルサーバーを `--ui-test` 付きで起動した場合だけ、プレビューを利用できます。
URLのパスは `/test/browser/reconciliation-demo/` です。
通常画面に模擬データを自動で取り込むことはありません。

プレビューでは次の3例を確認できます。

- DAT：100から107へ増加。履歴も7の増加なので一致。
- EMA：100から109へ増加。履歴は7の増加なので、2の差額。
- CAWELON：100から107へ増加。差額は0ですが、37〜39ブロックが未取得。

プレビューの金額とアドレスはテスト用です。
実際のウォレットで保有している残高を示すものではありません。

## この機能で保証しないこと

計算の一致は、保存した記録同士の整合性を示します。
現在のチェーン状態、履歴の完全性、作成者の身元、資産の安全性、利益を証明しません。
チェックサムも、ファイルの内容が変化していないかを確認するためのものです。
独立したセキュリティ監査やオンチェーン検証の代わりにはなりません。
