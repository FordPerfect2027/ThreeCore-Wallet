# 過去の期間を取得・保存して再開する

DAT・EMA・CAWELONの残高と送受信履歴を、指定した期間でまとめて読む機能です。
接続済みのカードを使用し、読み取れた部分をJSONファイルに保存できます。
通信が途中で止まった場合も、完成済みの部分を保って手動で再開できます。

この開発版はPC内での動作確認用です。
今回の作業ではGitHubへの反映を行っていません。

## 今回できること

- 開始・終了ブロックを自分で指定する。
- 開始時点と終了時点のトークン残高を取得する。
- その間のTransferイベントを、指定した大きさの区間に分けて読む。
- 取得途中の控えをファイルに保存する。
- 保存した控えの内容を確認して復元する。
- 保存時のブロック情報を再確認し、残りの区間を読む。
- 完了した記録を既存の照合画面に渡す。

署名、送金、トークンの承認、ブリッジ操作は追加していません。
画面を開いただけでは接続や読み取りを開始しません。

## 「開始」と「終了」の意味

ブロックは、チェーン上の記録のまとまりについた番号です。
ここで指定するのは日時ではなく、その番号です。

開始ブロックをA、終了ブロックをBとすると、次の内容を読みます。

| 項目 | 読み取る範囲 |
| --- | --- |
| 開始残高 | Aが終わった時点の残高 |
| 終了残高 | Bが終わった時点の残高 |
| 送受信履歴 | Aの次のブロックからBまで |

Aの中の送受信は、開始残高にすでに含まれています。
履歴でもAを含めると二重に数えるため、この画面の履歴は `(A, B]` です。

例としてA=30、B=42、1区間=5ブロックの場合は次の3区間になります。

| 区間 | 履歴の範囲 |
| --- | --- |
| 1 | 31〜35 |
| 2 | 36〜40 |
| 3 | 41〜42 |

開始残高・終了残高・3区間の履歴で、合計5工程です。
工程数は、通信の回数や残り秒数を表していません。

## 取得前に確認するもの

1. DAT・EMA・CAWELONのうち、今回対象にするカード。
2. カードに表示されたアカウントとチェーン。
3. 開始ブロックと終了ブロック。
4. 接続先がその時期の過去の残高を読めるかどうか。

接続先によっては古い状態を読めない場合があります。
その場合、この機能が別の接続先に自動で切り替えることはありません。
読み取れない残高をゼロとして表示することもありません。

## 新しく取得する手順

1. 通常のウォレット画面で対象カードを接続済みにします。
2. 「期間の取得・再開」の対象トークンを選びます。
3. 開始・終了ブロックと、1区間のブロック数を入力します。
4. 「期間の計画を確認」を押します。
5. アカウント、チェーン、範囲、工程数を確認します。
6. 「この内容を控えに反映」を押します。
7. 「取得を開始・再開」を押します。

計画を確認しただけ、または控えに反映しただけでは通信しません。
取得ボタンを押した段階で読み取りが始まります。

すでに取得した控えを別の計画に置き換えるときは、確認チェックが必要です。
残しておきたい記録は、先にJSON保存してください。
入力の変更や接続先の変更があると、確認中の計画は無効になります。

## 取得中の表示

画面には、次のような現在の処理が表示されます。

- 保存したブロック情報の再確認。
- 開始残高の読み取り。
- 終了残高の読み取り。
- 各区間の送信・受信履歴とブロック情報の確認。
- 全工程の後のブロック情報の再確認。

1つの工程が最後まで正常に終わった時点で、その工程が控えに追加されます。
途中まで届いた履歴を、区間全体の完成した記録として保存しません。

進捗は時間の見積もりではありません。
イベントが多い区間では、ブロック情報を確かめる処理が増えます。

## 途中で止まったとき

通信エラーや時間切れになった場合、取得済みの工程は画面内に残ります。
「処理を停止」を押した場合も同じです。

画面を閉じる前に「途中の控えをJSON保存」を押してください。
ブラウザーのダウンロード先にファイルがあることを確認してください。
ダウンロードの開始表示だけでは、ディスクへの保存完了を保証しません。

この控えは、画面のメモリー上に保持しています。
ページを再読み込みしたり閉じたりすると、保存していない控えは失われます。
既存のウォレット設定バックアップや履歴一覧への保存とは別の操作です。

## JSONを読み込んで再開する

1. 「期間取得のJSONを読み込む」で保存したファイルを選びます。
2. 復元候補のトークン、アカウント、範囲、工程数を確認します。
3. 必要な置き換え確認をして「この内容を控えに反映」を押します。
4. 元と同じトークン・チェーン・アカウントのカードを接続済みにします。
5. 「取得を開始・再開」を押します。

ファイルの読み込みだけではウォレット接続や通信を行いません。
接続していなくても、保存済みの内容を確認することはできます。

再開時は、保存したブロック番号とハッシュを現在の接続先で照合します。
一致した場合に、未取得の残高または次の履歴区間へ進みます。
取得済みの区間を重複して追加しません。

完成済みのJSONでも「取得を開始・再開」を押せます。
その場合は、保存されたブロック情報を再確認します。
保存済みの残高やイベントの中身を、すべて最初から再取得する操作ではありません。

## ブロック情報が変わっていた場合

保存時のブロックハッシュと一致しなければ、続きの取得を止めます。
古い控えを照合画面へ送る操作も、その画面では止めます。

まず、必要に応じて古い控えをJSON保存してください。
次に画面の「新しい計画を確認する」操作で、最初から取り直す案を確認します。
計画を反映して取得を開始するまでは、古い記録を自動で削除しません。

現在の画面では、直近に不一致になった同一の控えを読み直しても制限を保ちます。
この不一致の記憶はJSONには含めず、ページを閉じると失われます。
別の画面でファイルを開けたことだけを、正しい記録の証明にしないでください。

## 履歴が多すぎる場合

1区間のイベント件数などが上限を超えると、途中の結果を切り捨てて完成扱いにはしません。
「1区間を細かくする」計画案を表示します。

区間を細かくすると、12区間の上限に合わせて終了ブロックが手前になる場合があります。
その場合、今回の範囲と残りの範囲を分けて表示します。
残りは別の計画として取得する必要があります。

1ブロックだけでも上限を超える場合、この画面ではさらに分割できません。
控えを保存して、その区間の取得方法を別途確認する必要があります。

## 照合画面へ渡す

全工程が完成すると「照合画面へ確認候補を送る」が使えます。
押すと、対象トークンの残高2件と履歴が、既存の照合画面の候補になります。

照合画面側でも変更内容を確認して適用してください。
DATの候補を送っても、すでに保存してあるEMA・CAWELONの枠はそのままです。
別のトークンも同じ手順で取得すると、3つを一つの照合作業にまとめられます。

照合結果の一致は、記録された残高とイベントの計算が一致したという意味です。
トークンの安全性、接続先の正直さ、全取引の正しさを認定するものではありません。

## 保存するファイルの違い

| ボタン | 用途 |
| --- | --- |
| 途中の控えをJSON保存 | 途中・完成どちらの取得内容も保存し、後で再開する |
| 照合用JSONを保存 | 完成した内容を既存の照合用ファイルにする |
| 取得内容をテキスト保存 | 人が読みやすい要約として保存する |

テキストからの復元はできません。
JSONにはアカウント、残高、履歴、取引相手などが含まれます。
ファイルを共有する場合は、その内容も相手に渡ります。

チェックサムは、ファイルの破損や内容の不一致を見つけるためのものです。
暗号化、電子署名、第三者による認証ではありません。

## 現在の上限

| 項目 | 上限 |
| --- | --- |
| 1区間の長さ | 2,000ブロック |
| 1つの計画の区間数 | 12区間 |
| 1つの計画の履歴範囲 | 最大24,000ブロック |
| 1区間の採用イベント | 500件 |
| 1区間の異なるイベントブロック | 100個 |
| 1回の取得処理 | 既定120秒 |
| 残高・履歴の各読取工程 | 既定30秒 |
| JSONファイル | 24 MiB |
| 正規化された控え本体 | 16 MiB |

上限まで必ず取得できるという保証ではありません。
通信速度や接続先の対応状況によっては、途中保存と再開が必要です。

## 開発者向けのファイル確認

ウォレットの作業フォルダーで、次のコマンドを使えます。

```powershell
npm run period:check -- "C:\path\ThreeCore-period-DAT.json" --json
npm run period:check -- "C:\path\ThreeCore-period-DAT.json" --require-complete
```

終了コード0は形式・チェックサムの確認成功です。
`--require-complete`付きで未完成なら終了コード2です。
ファイルが壊れている場合などは終了コード1です。

この確認はファイルを変更せず、チェーンへも接続しません。
表示する要約には、完全なアカウントアドレスや残高を含めません。

## 模擬データで試す画面

`--ui-test`付きでローカルサーバーを起動すると、次を利用できます。

- `/test/browser/period-demo/`：保存・失敗・再開を手動で試す画面。
- `/test/browser/`：ブラウザー操作の自動テスト。

期間取得の体験画面に出る残高と履歴は、すべて作成した模擬データです。
実際のウォレット接続先や残高を表していません。
通常のウォレット画面は `/` です。
