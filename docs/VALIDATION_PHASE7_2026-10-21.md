## 完成した変更

3トークンの送金・承認履歴で、取得開始時の終了ブロックハッシュを保持し、各イベントの所属ブロックをRPCヘッダーと照合します。最後に終了ブロックとネットワークを再確認し、観測した変化があれば報告を破棄します。空の履歴も再確認します。

既存承認額は、終了ブロックのハッシュと正規チェーン要求を指定して読み取ります。非対応のサービスに対して番号や最新時点へ切り替えません。独自アダプターにはヘッダー取得とハッシュ指定の正しい実装が必要です。

Wallet側では、修正済みトークンの版へCIの固定先を更新しました。トークン側が使用するWallet機能版は引き続き `5985f44f8930324ed55cd49ffd51f9557e19b341` です。今回のWallet変更はCIと記録です。

## 検証

- 各トークンのローカル `npm run check` が成功。コンパイル・契約検査・型検査を含みます。
- 読み取り検査は各120件。今回追加した29件を含みます。
- 実際の契約ソースを配置した模擬EVMの履歴検査は各10件、計30件成功。
- 新しいブロックの追加では元の承認額7を保持し、最新の11と混同しません。
- 実際に模擬チェーンを巻き戻してブロックを置換すると検査を拒否します。再取得では置換後の11を取得できます。
- 実際に送られる `eth_call` がブロックハッシュと `requireCanonical: true` を使うことを、読み取り専用の検査用経路で確認しています。

検査用アダプターは、公開されたトークンアドレスをローカル配置先へ対応付けます。履歴・金額・ブロック情報は模擬EVMの応答を使用します。実際のBaseネットワークへは接続しません。

Wallet CIは、上記の各トークン検査に加えて、Wallet196件、HTTP配信2件、Chrome模擬画面8件、Wallet結合各24件（計72件）を継続します。[GitHub Actions](https://github.com/FordPrefect2026/ThreeCore-Wallet/actions)で当該コミットの結果を確認できます。同じケースの再実行を固有テストとして重複集計しません。

## 未検証・残る制約

- 履歴ヘッダーの照合は同じRPCからの応答に基づきます。独立した正規チェーン証明ではないため、`canonicalityVerified: false` を維持します。
- 範囲指定の履歴でRPCがイベントを省略することや、一時的に別のチェーンへ移った後に元へ戻る変化を完全には検出しません。`historyComplete: false` を維持します。取得後の再編成も防ぎません。
- 本番RPC各社、実Wallet拡張、外部dAppログイン完了、独立した安全性監査は未検証です。
- 公式Aerodromeのライブ模擬接続は今回は再実行していません。
- 実Walletでの署名・売買・送金・承認・LP追加、ゲーム開発は行っていません。
- Solidity契約、本番配備記録、供給量設定は変更していません。
