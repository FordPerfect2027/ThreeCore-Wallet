# 3トークンの公開残高取得と予算への転記

2026年11月3日の継続開発。先に追加した同一ブロックの公開RPC取得を、
画面から開始・中止・保存できるようにしました。取得後の予算への転記も追加しています。
この記録は全体90%達成の宣言ではありません。

## 使い方

新しいソースで `npm run demo` を起動し、Wallet冒頭の
「3トークンの公開残高を別タブで確認」を開きます。
今回の独立した確認先は `http://127.0.0.1:4245/tokens/read/` です。

1. 公開アドレスとBase SepoliaまたはBase Mainnetを選びます。
   ブロック欄を空にすると取得開始時の最新、入力するとその過去ブロックを使います。
2. 「3トークンを読み取る」でDAT・EMA・CAWELONとETHを取得します。
   口座・ネットワーク・ブロック番号の変更、画面終了、「読み取りを中止」で取り消します。
3. 完了後に表示した口座・ブロック・各トークン情報を確認し、JSONを保存できます。
   途中の結果や取り消した結果は表示・保存しません。
4. `/budget/`で対象トークン・ネットワークを選び、保存した公開残高ファイルを読みます。
   口座・ブロックをプレビューしてから「確認した残高を転記する」を押します。
5. トークン残高・ETH残高・小数桁数だけを転記します。使用予定額・確保額・予備資金・
   費用はそのままです。内容を確認して予算を再計算します。
6. 保存した予算と元の公開残高を `/budget/evidence/` で照合し、元記録ごと保管できます。

## 境界

公開残高画面はローカルの専用POST窓口を使います。Host・同一Origin・Fetch Metadataを
既存の境界で確認し、さらにPOST、JSON、完全一致のOriginを要求します。
入力は公開口座・対応ネットワーク・ブロック番号だけで、URLや任意RPCメソッドは渡せません。
入力上限1 KiB、リクエスト本文5秒、同時取得3件、取得全体120秒、各RPC10秒です。
応答切断は上流の読取も取り消し、枠を解放します。ブラウザー側も125秒で打ち切ります。

Base公式RPCの固定窓口にだけ問い合わせ、各残高・コード・メタデータを同一ブロックハッシュに
固定します。最後に同じ高さのハッシュを再確認します。非対応RPCや再編時は別方式へ
自動で切り替えません。MetaMask呼出し、権限要求、署名、送金、秘密鍵取得はありません。

公開残高ファイルは32 KiB以内で、SHA-256と厳密な構造を確認します。
転記先とネットワークが違う場合、選択トークンの情報が登録内容と一致しない場合、
コントラクトや残高が未確認の場合は転記できません。確認中の編集・別ファイル選択・
取消・画面終了でプレビューを失効させ、遅延完了も破棄します。

チェックサムは発行者や口座所有者の証明ではありません。残高は過去の指定ブロック時点です。
予算を転記しても費用は見積もらず、実行を許可しません。

## 実画面で確認した結果

Codex内ブラウザーでAccount 2の公開アドレスを使い、次を実施しました。

- Sepoliaのブロック53876331を指定して取得・保存。先のコマンド取得とバイト単位で一致。
  1678 bytes、SHA-256 `7d026b28e4016b956e22fc60b1b1f3f07d33210fbe4291e85ad57731a26dfca8`。
- 取得直後に中止し、途中結果が表示されず保存もできない状態を確認。
  最初の中止クリックは取得完了後で無効だったため、開始と中止を連続操作して再確認しました。
- Mainnetのブロック53454110を指定して取得・保存。先のコマンド取得と完全に一致。
  1692 bytes、SHA-256 `4a4596c54c600dad8201e894839d11be4d3f30a18310f510e79bc8f16c5ea470`。
- Sepoliaの保存ファイルと既存の仮予算を照合し、3トークンの整合を確認。
  4453 bytesの照合保存が先の期待ファイルと一致。予算不足・未確認という別判定は維持。
- Mainnetの保存残高をDATの予算へプレビュー後に転記し、再計算・保存。
  残高以外の使用予定額・予備資金・費用は検証用の仮入力を維持。
  運営者費用の不明を0に変えず、元本不足と費用未確定を表示。

金額・口座入りの原本はDownloadsに保管しています。このリポジトリにはブロック番号・
ハッシュ・テスト結果・ファイルチェックサムなどの検証要約を保存します。
元の4231・4232・4233は変更せず、HTTPで応答を確認しました。
