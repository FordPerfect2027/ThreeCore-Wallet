# Inspect a complete manifest of original wallet save files

Item 516. Source: `2f87c4c`.

The new local command accepts an explicit SHA256SUMS list of at most 50 JSON files, 16 MiB each and 64 MiB total. It verifies exact external file hashes before invoking the existing independent original-file inspector. Supported originals are period drafts, period libraries, three-token period reports, report-history backups and report sets. Their full structure and internal checksums are checked; archive/re-plan flags and draft-reference counts remain visible. Known auxiliary declarations receive destination guidance only and cannot inherit their own claims of verification. No report contents, addresses, balances or note text are copied into the inventory; selected filenames remain visible.

Files are opened read-only beneath the real manifest directory. The implementation refuses paths outside that directory, manifest self-reference, duplicate resolved paths or physical file aliases, changed opened files, invalid UTF-8 and excessive byte/count limits. The manifest is checked before and after the batch; a changed manifest suppresses the entire result. Each admitted file has its own stable-read and post-inspection metadata checks. This is not an atomic snapshot of multiple files and does not authenticate their origin or recheck a chain. Unreadable or unstable rows cannot produce a globally matching result, even if an earlier byte hash is retained for diagnosis.

JSON keeps distinct validated-original, declared-only, checksum-mismatch and unreadable statuses, per-file diagnostics, fingerprints, limits and inspection scope. CSV repeats global scope/limitations and retains every selected row, including failures, with formula-leading filenames escaped and unknown values blank. All columns should be imported as text. Results are viewing inventories, not restorable backups; repeated draft references across reports are not summed into independent verification counts or balances.

Run `node scripts/inspect-wallet-saved-batch.js SHA256SUMS.txt`; append `--format csv` for the viewing table. Exit 0 means every listed file is a validated original. Exit 2 preserves any per-file failure or auxiliary-only result; exit 1 indicates invalid arguments or a bad/changing manifest. The command writes only its requested output stream, never source files, imports, repairs or network requests.
