# ThreeCore全体の開発対象と次の実装

2026年11月3日、ユーザーは90%の対象を「Token・Wallet・AI・dAppを含む構想全体」と明示した。
読み取り専用Walletの配布完了は、この全体目標の完了を意味しない。
既存の実口座に関する署名・送金・承認取引・秘密鍵取得の禁止は継続する。

## 現在の根拠と残る接続部分

| 分野 | 確認できる実装・証拠 | 全体に向けて残る部分 |
| --- | --- | --- |
| Token | DAT・EMA・CAWELONの固定ソース、コンパイル・設定検査、隔離したEVMでの契約と履歴試験。公開チェーンでのコード存在・メタデータ・同一ブロック残高。 | 公開先の契約と採用するソース・権限・配布条件を結び付けた最終構成。メタデータ一致だけを配備コードの同一性とみなさない。 |
| Wallet | 実MetaMask接続、口座・ネットワーク変更時の無効化、読み取り、原本保存・照合・復元。 | 提案から事前確認・費用・許可条件へ進む一貫した画面。取引実行部分は未実装。実口座の操作を使わず、まず隔離環境で設計・検証する。 |
| AI | 本開発でのAI支援はあるが、製品内のAI提案経路としての実装・検証は未確認。 | 提案の入力・出力形式、出典となる観測記録、検証可能な根拠、期限・口座・ネットワークの拘束。AIの文章だけで実行権限を作らない。 |
| dApp | 読み取り専用の契約・残高・既存承認額の事前確認と、模擬Walletによる外部接続試験。 | 対象サービスと契約を明示する連携、見積もり・価格影響・期限・障害時処理を提案と結び付ける。実Walletによる外部ログインを実証済みと扱わない。 |
| 資金使用条件 | トークンとETHを分けた予算、共有口座の集計、公開残高の確認後転記、原本との整合照合。 | DAT・EMA・CAWELONごとの使用上限・対象・期限、提案と予算の一致、実行前の費用と状態変化の扱い。現状の予算結果は権限ではない。 |
| 配布・復旧 | 固定ソース4組をまとめた検証済み旧パッケージ。追加機能を含む新しい統合検証・パッケージを進行中。 | 現行機能をまとめた新しい復元・起動・保存データ再読込の記録。次の機能追加後も対象ソースを明確にする。 |

## 次の実装順

1. 現行の公開読み取り・予算機能までをまとめ、総合検証と新規保存先での復元を完了する。
2. 提案、対象dApp、口座・ネットワーク、原本のブロック、予算、使用条件を結ぶ
   検査可能なデータ形式を追加する。まずオフラインで一致・不一致・期限超過を検査し、
   未完成の条件を実行可能として表示しない。
3. その形式を製品内のAI提案経路につなぐ。外部AIを利用する場合は、既存の適切な接続を
   確認し、必要な認証・データ送信の意思決定だけをユーザーへ確認する。
4. 対象dAppの読取・見積もりを統合する。実行系の開発検証は既存の隔離EVMを優先し、
   実口座での署名・送信の許可とは切り離す。

資金を入れた3口座の用意や、繰り返しのMetaMask切り替えは、上記のオフライン実装を
進めるための前提ではない。完了済みの検証を繰り返して機能数・割合を増やさない。
進捗は、この表の残る機能と実際の完了根拠を更新して判断する。
