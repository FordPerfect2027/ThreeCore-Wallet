# Portable wallet saved-file batch evidence

Item 554. Source: 8fd952f.

The wallet's saved-file batch panel can now save exact source files and a freshly inspected receipt in one JSON document. Source-content consent is separate from metadata-only saving. It retains public addresses, recorded balances, restrictions and notes in plaintext, explicitly disclosed before saving. The capture is limited to 24 MiB combined sources and 48 MiB serialized evidence; ordinary inspection still permits 64 MiB total. Larger source selections are not retained for this packing feature. Successful earlier source captures survive continuation/retry without rereading those files. Incomplete, unreadable or unhashed sources cannot produce a bundle. Packing performs a fresh inspection snapshot; earlier interruption/retry chronology remains in separately saved receipts.

On reopening, every stored claim is compared with a fresh inspection of the exact embedded source bytes and reference. Only an owned matching review exposes sources to the list; callbacks receive new File objects containing those exact bytes plus their verified text digest. Altered claims preserve the previous list and can be saved as a negative verification record. Original internal checksums, structural-only inputs, auxiliary claims, invalid files and external mismatches stay distinct. Faithful evidence can pass while allOriginalsValidated remains false. No balances are summed and no history/settings are imported. Stop, clear, new selections, failed download delivery and disposal preserve ownership and suppress stale output.

The offline command is: node scripts/verify-wallet-batch-evidence.js evidence.json. It writes to stdout only. Exit 0 means faithful evidence, including faithful negative or structurally valid plain sources; exit 2 means altered claims; exit 1 means invalid/incomplete input. Read allOriginalsValidated and expectedSummary separately. Verification does not authenticate origin, recheck a chain or certify the original read chronology.
