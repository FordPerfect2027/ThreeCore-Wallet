# 元本・ETH費用と共通口座の予算確認

2026年11月3日のローカル開発。既存の運用リハーサルで1種類の仮想資産に
まとめていた元本と費用を、トークンとETHに分けて確認できる画面を追加しました。
さらに、DAT・EMA・CAWELONが同じ口座を使う仮定で、各計画が同じETHを
重複して使えると判定しない合計確認を追加しました。

## 使い方

新しいソースで `npm run demo` を起動し、`/budget/` を開きます。
運用リハーサルの冒頭から別タブでも開けます。今回の独立した確認用サーバーは
`http://127.0.0.1:4242/budget/` です。元の4231・4232・4233は変更していません。

1. トークン・ネットワーク・小数桁数、元本、ETH残高、別用途の確保額、予備資金、
   費用の仮定を入力します。「仮の入力例」は現在の残高や相場ではありません。
2. 予算を確認し、必要に応じて「確認した入力を保存」でJSONを保存します。
3. 同じ口座で複数トークンを使う場合は「同じ口座のETH予算をまとめて確認する」を開きます。
4. 異なるトークンの入力を2〜3個選び、同じ口座・同じ時点の仮定を確認して計算します。
5. まとめた入力も保存・読み戻しできます。読み戻し時にも同じ口座の仮定を再確認します。

必要欄の空白や小数精度の超過は受け付けません。L1データ費用と運営者費用のみ、
空白は「不明」です。0は「費用なしという入力上の仮定」であり、空白とは区別します。
不明な項目を0とみなして十分な予算と判定することはありません。

## 計算と境界

トークンの必要額は、別用途の確保額＋予備資金＋今回使う元本です。
ETHの必要額は、別用途の確保額＋予備資金＋費用以外に使うETH＋費用予算です。
費用予算はガス上限×1ガスあたりの上限に、L1データ費用・運営者費用・余裕分を加えます。
Baseの費用項目の分離には[公式の費用仕様](https://docs.base.org/specifications/transactions/network-fees)を参照しました。
現在のガス価格は取得・固定していません。

共通口座ではETH残高・別用途の確保額・予備資金を全入力で一致させ、
共通の確保額と予備資金を1回だけ数えます。各計画の費用とETH使用額はすべて足します。
異なるネットワーク、重複トークン、不一致の共通残高は合計できません。
DAT・EMA・CAWELONの元本同士は合算しません。

金額は整数の最小単位で計算し、uint256の乗算・加算超過を拒否します。
JSONは重複キー・未知の項目・不正な構造を拒否し、単独入力16 KiB、まとめ入力48 KiBを上限とします。
ファイル読み込みは取消・別ファイル選択・ページ離脱で失効し、遅れて返る内容を適用しません。
入力や仮定を変更すると古い計算結果と保存可否を解除します。

## 実際に確認した結果

単独予算の画面では、不明費用と0の区別、ETH不足、入力変更による古い結果の解除、
ファイルの確認・復元・再計算・再保存を確認しました。
679 bytesの保存と再保存が一致し、SHA-256は
`be10ab6ff7af92f82f2cded2589b0f19012020263ae7328e2d76af6de60dc933` です。
[単独予算の記録](evidence/2026-11-03-operation-budget/summary.json)。

共通口座の実画面では、3トークン各50単位、各費用0.00004 ETH、
共通残高0.00306 ETH、確保額0.001 ETH、予備資金0.002 ETHという仮入力を使いました。
それぞれ単独の必要額は0.00304 ETHですが、3件では0.00312 ETHとなり、
**0.00006 ETH不足**することを確認しました。実際の資産を使った結果ではありません。

保存→読み戻し→再計算→再保存した2476 bytesが完全一致し、SHA-256は
`e0062324c488e1ff341d828ce38aba3cbad24251500697b64d9a7cffc9f58736` です。
画面外の計算も同じ結果でした。[共通口座の記録](evidence/2026-11-03-shared-budget/summary.json)。
最終の関連検証は683件成功、失敗・取消・スキップ0件です。
新機能の45件はこの683件に含まれ、機能数や進捗率を意味しません。
既存Wallet全体の回帰を今回再実行したとは主張しません。

最初の単独予算テストでは、存在しないファイル読込スコープの`dispose`を呼ぶ不具合で
11件が失敗しました。既存の`cancel`経由の後始末に修正し、同じテストが成功しています。
初回表示の不要な「入力が変わった」表示も修正しました。元の失敗を成功扱いにはしていません。

## 画面外での再確認

```powershell
npm run budget:check -- saved-input.json
npm run budget:shared -- --same-account DAT.json EMA.json CAWELON.json
npm run budget:shared -- --saved ThreeCore-shared-budget-input.json
```

終了値0は入力した仮定上の予算内、2は不足・不明、1は不正入力・読込失敗です。
入力ファイルを書き換えず、ファイルのSHA-256と計算結果を出します。
2は正しく不足を検出した結果であり、ツールが壊れた意味ではありません。

## 残る範囲

同じ口座であることも、残高・費用・予約済み資金も手入力の仮定です。
現在のチェーン観測、口座所有、ブロックの新しさ、コントラクト、dApp見積もり、
価格影響、nonce、実行順序、取引結果は検証しません。
未知の費用がある場合、表示する「分かっている必要額の下限」は総額ではありません。
この計算は実行許可や実際の請求上限を与えません。

既存Walletの残高観測には口座・ネットワーク・ブロック・トークンの情報がありますが、
今回の予算ファイルはまだそれに結び付いていません。次の開発対象は、その保存済み観測を
出典付きで取り込む流れと、異なる口座・ブロックや古い観測を混ぜない確認です。
手入力の現在値や認証済み残高に見せないことが必要です。

既存の運用リハーサル保存形式は変更しておらず、この新機能の入力は別ファイルです。
GitHub反映は保留中です。以前の`ThreeCore-complete-4dfa300-20261103.zip`は
固定された以前の成果物であり、この追加機能は含まれません。
これらの機能追加だけで全体90%やメインネット公開条件の達成とはしません。
