# 予算と保存済み残高の照合

2026年11月3日。手入力の予算を、既存Walletから保存したコントラクト情報・残高の
観測記録に結び付ける確認画面を追加しました。`/budget/evidence/` を開くか、
単独予算・共通口座予算の画面から別タブで開けます。
今回の新しい確認用サーバーは `http://127.0.0.1:4243/budget/evidence/` です。

## 手順

1. 予算入力または共通口座の予算ファイル1個と、対応するトークンの
   「コントラクト情報・残高」ファイル1〜3個を選びます。
2. 「読み込んだファイルを照合」で元記録のチェックサムと内容を確認します。
3. 結果の画面で口座・ネットワーク・ブロック、残高の一致を確認できます。
4. 「元の記録と予算をまとめて保存」で、予算と元記録の全文を含むJSONを保存します。
5. 保存した照合ファイル1個を読み戻せば、同じ確認を再実行できます。

入力元のファイルは変更しません。照合ファイルには公開アドレスと残高記録が含まれます。
通常のWalletバックアップや送受信履歴とは別の形式です。

## 判定の意味

トークンごとに、ネットワーク・小数桁数・トークン残高・ETH残高を照合します。
参照するコントラクトが既存のトークン一覧に一致し、コードとメタデータが確認済みの
記録であることも既存の検査処理で調べます。不明な残高を0に置き換えません。

共通口座の予算では、全記録の口座・ネットワーク・ブロック番号・ブロックハッシュ・
ETH残高の一致を要求します。欠けたトークン、余分なトークン、同じトークンの重複も
通しません。個別の残高が一致していても、共通の取得時点が違えば全体は不一致です。

「保存記録と整合」と「入力した予算が足りる」は別の結論です。
過去の残高0と予算入力の0は整合しても、予定した元本・費用には不足し得ます。
チェックサムは元記録の一貫性を検査するもので、発行者やチェーン上の真実性を証明しません。
現在の残高・費用を取得したり、実行を許可したりする機能ではありません。

## 実保存記録を使った確認

既存のAccount 2・Base Sepoliaの3ファイルを使い、予算の残高をその記録の値にそろえました。
元本の使用予定と費用はテスト用の仮定で、実際の運用指示ではありません。

| 記録 | ブロック | 観測されたトークン・ETH残高 | まとめた結果 |
| --- | --- | --- | --- |
| DAT | 53,413,786 | いずれも0 | EMAとの2件では同一口座・同一ブロックで整合 |
| EMA | 53,413,786 | いずれも0 | DATとの2件では同一口座・同一ブロックで整合 |
| CAWELON | 53,413,972 | いずれも0 | 3件をまとめるとブロック不一致 |

3件では個別の残高がすべて一致しても `SOURCE_BLOCK_MISMATCH` を検出しました。
実画面と画面外の計算が同じ結果です。保存→読込→再照合→再保存の5693 bytesが一致し、
SHA-256は `de043fec88e2bea13dbadaf99a63d0017b19ed1fc3998b7d469ec675570eace1` です。

DAT・EMAの2件では整合を確認できました。こちらの保存は3862 bytes、SHA-256は
`eb0a7d9d56b832a9496082bae589d5797d0c092f24c6e7ed7202e0d7817fc878` です。
予算の不足・不明という表示は維持されています。元の3ファイルのハッシュは変更されていません。

フルアドレスを含むファイルと画像はDownloadsに保存し、リポジトリには
[検証要約](evidence/2026-11-03-budget-observation/summary.json)、ソース一覧、
テスト記録とチェックサムを保存しています。
ブラウザーはCodex内蔵ブラウザーです。新たなWallet接続やチェーン読み取りは行っていません。

## 検証と再現

関連920件が成功、失敗・取消・スキップ0件です。予算・元記録デコーダー・既存リハーサル・
HTTP配信を含む検証であり、Wallet全体を今回再実行した結果ではありません。
入力中やチェックサム確認中の取消、別ファイル、ページ離脱、破損、遅延完了、保存中の
再操作を含みます。古い照合結果を新しい入力の結果として保存しません。

```powershell
npm run budget:evidence -- ThreeCore-budget-evidence.json
```

終了値0は記録との整合と仮定上の予算内、2は整合不一致または予算の不足・不明、
1はファイル不正・読み取り失敗です。出力は元ファイルのSHA-256、各トークンの理由、
共通口座の不一致理由、予算計算を分けて保持します。原本は書き換えません。
