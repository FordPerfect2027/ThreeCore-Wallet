# 3トークンを同じブロックから読み取る

2026年11月3日。別々の時点で取得された3トークンの残高を混ぜないため、
同じ公開アドレス・同じネットワーク・同じブロックハッシュに固定した一括読取を追加しました。
読み取り元は固定されたBase公開RPCです。MetaMaskの接続や権限、口座所有を示す結果ではありません。

## 読み取りの流れ

1. 入力したネットワークと公開アドレス、指定がある場合はブロック番号を検査します。
2. 固定RPCにネットワーク番号を確認します。現在ブロックを使う場合は、その番号を取得します。
3. 対象番号のブロックハッシュを取得します。
4. ETH残高を1回、DAT・EMA・CAWELONのコード・メタデータ・残高を順次読み取ります。
   各呼び出しは同じハッシュと `requireCanonical: true` に固定します。
5. 終了前に同じ番号のブロックハッシュを再取得し、最初と一致することを確認します。
6. 完了した内容を、公開RPC由来でWallet接続を伴わない新しい保存形式にまとめます。

途中のエラー・取消・期限超過・ブロックの変化では、部分的な記録を完成品として返しません。
ハッシュ指定を拒否された場合に、最新ブロックや別RPCへ自動的に切り替えることもありません。
コードがないトークンは残高を不明として保存し、0とは区別します。
メタデータが登録内容と違う場合、取得できた事実とトークン情報の一致を分けて扱います。

個々の要求は通常10秒、処理全体は通常120秒を上限とし、既存の応答サイズ制限を使います。
公開RPCのメソッドにはネイティブ残高と4種類の引数なしメタデータ読取だけを追加しました。
署名、送信、口座要求、許可変更、任意の取引内容は受け付けません。

## コマンド

新しい公開読み取りでは、ネットワークと公開アドレスを明示します。
`--block` を付けると、指定した10進数の過去ブロックを読み取ります。
`--output` は新規ファイルのみ保存でき、既存ファイルがある場合は通信前に停止します。

```powershell
npm run tokens:read -- --network sepolia --account 0xPUBLIC_ADDRESS --output new-public-batch.json
npm run tokens:read -- --network mainnet --account 0xPUBLIC_ADDRESS --block DECIMAL_HEIGHT --output new-historical-batch.json
npm run tokens:read -- --check saved-public-batch.json
```

上記の公開アドレスとブロック番号は実際の値に置き換えます。
最後の`--check`はオフラインの再検証で、通信も原本変更も行いません。
`--help`と不正引数も通信しません。秘密鍵やシードフレーズを入力する引数はありません。

## 検証と継続範囲

関連1058件が成功、失敗・取消・スキップ0件です。公開RPCの既存利用先、予算、
記録デコーダー、リハーサル、HTTP配信を対象とします。全Wallet回帰の再実行ではありません。
ネットワーク違い、ブロック変化、ハッシュ指定拒否、不正な残高・メタデータ、取消後の
遅延完了、入力検査、原本を上書きしない保存、破損ファイルを含みます。

この段階では取得操作はコマンドから行っていました。後続の
[画面取得と予算への転記](PUBLIC_TOKEN_BATCH_UI_2026-11-03.md)により、
画面から明示的に開始・取消・保存し、公開残高を予算へ転記できるようになりました。
既存Walletの署名・送信機能、実行前の費用見積もり、価格影響・実行順序・資金使用許可は
この変更に含まれません。全体90%達成という結論には置き換えていません。
