## 今回の成果

3トークン共通の送金・承認履歴処理で、除外済みイベントやuint256上限を超える金額を受け入れる問題を修正しました。変更前のDATソースで4ケースを再現し、修正後の境界条件検査を各トークンで実行しています。

新しい検査は、完全なブロック・取引ハッシュ、確定済み位置情報、`removed: false` を要求します。同じブロック・取引・ログの位置に食い違うデータがあれば報告全体を失敗にします。送受信フィルターの違反も拒否し、正常な重複履歴と自己送金の重複除去を維持します。

Wallet側では、修正済みトークンの版を固定し、既存のWallet結合検査に加えてトークンの読み取り・履歴検査をCIへ組み込みました。トークン側CIが指定するWalletの機能版は `5985f44f8930324ed55cd49ffd51f9557e19b341` です。今回のWallet変更はCIと検証記録であり、接続や署名の機能を追加していません。

## 実行したローカル検査

- 各トークンのコンパイル・契約検査・型検査を含む `npm run check` が成功。
- 読み取り検査は各91件。今回追加した26件を含みます。
- 実際の契約ソースを配置した模擬EVMの履歴検査は各7件、計21件成功。
- 模擬EVMでは発行・送金・自己送金・焼却、承認額の消費、最大承認と取消を確認しました。実際のイベントへ異常な除外フラグや矛盾した位置を注入する検査も行っています。

履歴検査用のアダプターは公開済みの契約アドレスをローカル配置アドレスへ対応付けます。金額・ブロックハッシュ・取引位置は模擬EVMの実際の応答です。本番配置済み契約の検査ではありません。読み取り前後の供給量・残高・承認額・nonce・ブロックを比較し、検査自身がチェーン状態を変えないことも確認しました。

- Walletオフライン196件。
- ページ配信2件、模擬providerを使ったChrome画面操作8件。

各テストの成功・失敗は[GitHub Actions](https://github.com/FordPrefect2026/ThreeCore-Wallet/actions)の当該コミットで確認できます。複数のCIや検査手順で同じケースを再実行するため、件数を単純合算して固有のテスト数とは扱いません。

## 未検証・制約

- 履歴内の矛盾検査は、正規チェーンであることの独立した証明ではありません。報告には `canonicalityVerified: false` と `historyComplete: false` を残します。
- 承認履歴と既存承認額の取得はブロック番号による指定です。Walletのブロックハッシュ固定の事前検査とは別の処理で、取得途中のチェーン再編成を完全に防ぐものではありません。
- 必須の除外フラグや識別情報を返さない独自providerは、検査に失敗します。本番RPC各社との互換性は今回は検証していません。
- 公式Aerodromeの模擬接続は今回は再実行していません。実Wallet拡張、外部dAppログイン完了、独立した安全性監査は未検証です。
- 実Walletの署名・売買・送金・承認・LP追加、ゲーム開発は行っていません。
