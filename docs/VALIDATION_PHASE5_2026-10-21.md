## 修正内容

接続許可や残高取得の応答が遅れて届くと、切断後の表示や変更後の入力と食い違う可能性がありました。各カードの接続と表示を管理する処理を分離し、現在の操作に属する結果だけを反映します。

- 接続中の連打で許可要求を増やさず、待機中も切断できます。
- 切断、接続先の変更、Wallet側のアカウント・チェーン変更で残高と検査結果を消します。古い応答やイベントは新しい接続を上書きしません。
- トークン・承認先の入力変更で古い結果を消し、実行時の入力値を読み取り終了まで保持します。
- 通常の残高参照でも、ETH残高・トークンコード・トークン残高・既存承認額を同じブロックハッシュへ固定し、最後に同じ高さのハッシュを再確認します。
- コードがないトークンの残高を0と断定せず、確認できない旨を表示します。
- Wallet名は文字列として表示します。ページを離れる際はイベント監視を解除し、履歴から戻っても自動接続しません。

## ローカルで実行した検証

- オフライン回帰検査：196件。今回の画面状態管理の17件を含みます。
- 実際の各トークンソースを配置した模擬EVMとの結合検査：各24件、計72件成功。チェーンID 8453・84532で各12件です。実際のBaseネットワークではありません。
- 新しい結合検査では、画面用の制御処理を通して各トークンの初期供給量・承認額0・ETH残高を取得し、切断で表示用データが消えることを確認しました。

ローカル環境の通信制限により、ループバックHTTP接続は `EACCES`、アプリ内ブラウザーの接続はタイムアウトしました。このため、HTTP検査とブラウザー検査はGitHub CIで実行する構成にしています。ローカルで成功した検査としては扱いません。

## GitHub CIで追加実行する検証

2件のHTTP検査で、必要な画面・モジュールの配信、テストページの明示的な有効化、未許可ファイルの404応答を確認します。

Chromeの実DOM上で、次の8件を実行します。使い捨てのプロファイルを作成し、Wallet拡張を無効にし、明示的に渡した模擬providerだけを使います。テストページの通信制限も外部RPCを禁止します。

1. 接続中の連打で許可要求が増えない。
2. 切断後の遅い接続エラーが表示を上書きしない。
3. 残高・承認額・参照ブロックが表示され、取得先が同じハッシュである。
4. 読み取り中のトークン変更で古い残高を表示しない。
5. dApp検査中の切断で古い結果を表示しない。
6. Wallet側のアカウント変更で結果を消し、自動接続しない。
7. Wallet名にHTMLらしい文字列があっても実行せず、選択変更で切断する。
8. 他エージェントと同じアドレスを接続要求前に拒否する。

実行結果は[このリポジトリのActions](https://github.com/FordPrefect2026/ThreeCore-Wallet/actions)で該当コミットを確認できます。CIはブラウザーの完了状態と8件の成功を検査し、未完了や失敗を成功扱いしません。

## 再実行

```sh
npm run check
npm run test:demo-server
npm run test:browser-ui
```

自動ブラウザー検査はLinuxと `google-chrome` が必要です。手動では `npm run demo -- --ui-test` で起動し、表示されたローカルURLの `/test/browser/` を開きます。

トークンとの結合検査は、コンパイル済みの各トークンのディレクトリから実行します。

```sh
node --test ../ThreeCore-Wallet/integration/token-compatibility.test.mjs
```

## 未検証・範囲

- 実Wallet拡張での動作、実サービスのブロックハッシュ指定への対応、実Walletによる外部dAppログイン完了は未検証です。
- 公式Aerodromeのライブ模擬接続は今回は再実行していません。以前の模擬検証は署名要求を拒否する地点までであり、ログインや取引の完了を意味しません。
- 模擬providerのChrome検査は接続画面の操作検証です。外部dAppや契約の安全性を保証するものではありません。独立したセキュリティ監査も未実施です。
- 読み取りサービスの正しい応答を前提とします。取得後に発生するブロック変更を防ぐものではありません。
- 実Walletでの署名・売買・送金・承認・LP追加、ゲーム開発は行っていません。模擬EVM内の契約操作はテスト用アカウントだけを使います。
- トークンのSolidityソース・本番配備記録・供給量は変更していません。行数増加を成果の判定条件にはしていません。
