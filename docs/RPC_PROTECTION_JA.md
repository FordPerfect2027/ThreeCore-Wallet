# Walletの応答保護

対象はPC内のThreeCore Wallet開発版です。
今回の変更はGitHubや公開サイトへ反映していません。

## 何を守るための変更か

接続や残高確認を止めても、Wallet拡張機能がすでに受け取った要求は
そのまま処理を続けている場合があります。
画面を再接続するたびに、その未完了の要求を忘れてしまうと、
応答が戻らない要求を積み重ねることになります。

今回の保護では、画面が待つ時間とWallet側の未完了件数を分けました。
停止後の応答は残高表示へ戻しません。
未完了の要求が多いときは、新たな要求の送出を止めます。
DAT・EMA・CAWELONの画面は、この件数を共有しています。

## 画面に表示するもの

接続保護の近くに「Walletの応答保護」があります。
Walletアドレスや残高ではなく、処理の件数を表示します。

| 表示 | 意味 |
| --- | --- |
| 応答待ち | この画面がまだ結果を待っている要求 |
| 未完了 | Walletから結果が戻っていない要求の合計 |
| 待機終了後も未完了 | 停止や時間切れで画面は待つのをやめたが、Wallet側では未完了の要求 |
| 時間切れ | この画面の期限を超えて終了した待機 |
| 受付拒否 | 未完了件数の上限で送出しなかった要求 |
| 遅い結果の破棄 | 停止後などに戻り、表示へ採用しなかった結果 |

未完了が0件でも、Walletやチェーン全体の安全性を証明するものではありません。
この数字は、そのページで管理している要求についての情報です。
別のタブや再読み込み前のページの要求は集計に含まれません。

## 通常の残高確認

1. 確認するトークンの公開アドレスとチェーンを選びます。
2. 必要なWalletを明示的に接続します。
3. 「残高を参照」を押します。
4. 結果が戻ると応答待ちが減り、残高が表示されます。

この機能は読み取り用です。
応答保護の表示を開いても、送金、署名、トークン承認は実行されません。

## 応答が戻らない場合

読み取りには待機期限があります。
期限を過ぎると、その結果を待つのをやめます。
Wallet側で処理が残っていれば「待機終了後も未完了」に残ります。
結果が後から戻っても、終了済みの残高欄へは反映しません。

応答がない状態で接続操作を繰り返す必要はありません。
まずWalletの画面に未処理の接続確認がないか確認してください。
拡張機能そのもののロックや許可の取り消しはWallet側で行います。

## 接続を停止した場合

「3トークンの接続を停止」で、3つのカードの読み取りを停止します。
すでに表示した読み取り結果や一時的な復元候補も保護処理の対象です。
PC内に保存済みの履歴やバックアップファイルは削除しません。

通常の停止では「接続操作を再開する」を押した後、必要なカードで
接続し直します。再開ボタンだけでWalletへ自動接続はしません。
未完了の要求は、再開ボタンでは消えません。

## 時間を正しく確認できない場合

期限の判断に使う時間が逆戻りするなど、時間を信用できなくなった場合、
このページは接続を停止して新しい要求を受け付けなくなります。
待機中ではなかったカードも停止します。
この状態では通常の再開ボタンで保護を解除できません。

故障状態のまま接続を繰り返さず、表示された状況を確認してください。
ページを再読み込みしても、拡張機能が以前の要求を取消したことにはなりません。

## 接続変更の通知が異常な場合

Walletのアカウントやチェーン変更は、接続状態を確認するための通知です。
形式が不正な通知や極端に多い通知は、その接続を停止する原因になります。
通知そのものを、再接続や送金の許可には使いません。

## 今回の確認範囲

模擬Walletで、通常の応答、遅延、時間切れ、取消、過剰な通知、
不正なデータ、古い応答、複数トークンの停止を確認しています。
実Walletで新しく署名や送金を試すための変更ではありません。
第三者のセキュリティ監査が完了したという意味でもありません。
