# 期間の控えをPC内に保存する

この機能は、DAT・EMA・CAWELONの期間取得で作った控えを、
名前付きの一覧としてブラウザー内に保管するためのものです。
GitHubへの公開や、クラウドへの送信は行いません。

## できること

- 取得途中と取得済みの控えを、別々の名前で残す。
- 画面を開き直してから、以前の控えを選び直す。
- トークン・取得状態・保管状態・名前・公開アドレスで探す。
- 選んだ控えと、いま期間画面にある控えとの差を確認する。
- 名前を変更し、普段使わない控えを非表示保管にする。
- 一覧全体または選択した1件をJSONに保全する。
- 一覧の要約をCSVに保存する。
- JSONから一覧へ追加する前に、追加件数を確認する。

## まず保存する

1. 「期間を選んで、残高の変化を確かめる」の画面で控えを作ります。
2. 「期間の保存一覧を開く・再読み込み」を押します。
3. 保存名を入力します。例：DAT 10月24日 午前 途中。
4. 「現在の控えの保存内容を確認」を押します。
5. トークン・チェーン・公開アドレス・期間・取得工程を確認します。
6. 「確認した保存一覧の操作を実行」を押します。
7. 「PC内の保存が完了しました」という表示を確認します。

保存ボタンを押すまで、自動では保存しません。
取得が進んだ控えは、新しい記録として追加されます。
以前の途中版は上書きされません。

同じ内容の控えを重ねて保存しようとすると、重複を知らせます。
名前だけ変えたい場合は、既存の控えを選んで名前を変更してください。

## 開き直して続きを確認する

1. 保存時と同じブラウザー・同じ接続先URLを開きます。
2. 保存一覧を開き、目的の控えを選びます。
3. 「選択した控えの復元内容を確認」を押します。
4. 内容を確認して操作を実行します。
5. 下の期間画面に復元候補が表示されます。
6. 期間画面の内容を確認し、「この内容を控えに反映」を押します。
7. 続きを取得する場合だけ、「取得を開始・再開」を押します。

復元候補を出しただけではウォレットに読み取り要求を送りません。
現在の作業を置き換える場合は、期間画面で置き換えの確認が必要です。

実際の取得再開には、元の控えと同じトークン・チェーン・アドレスへの接続が必要です。
別のアドレスの控えを見ても、現在の接続先を書き換えません。

## 一覧の状態

| 表示 | 意味 |
| --- | --- |
| 途中 | 計画の一部だけを取得しています。 |
| 取得済み | その計画に含まれる工程の記録があります。 |
| 再取得が必要 | ブロック不一致などで、その控えをそのまま再開できません。 |
| 非表示保管 | 通常一覧から隠しています。データは残っています。 |

「取得済み」は現在の残高や全取引履歴を保証する表示ではありません。
保存された過去の記録です。
再開時には既存のブロック確認が行われます。

「再取得が必要」の印は、一覧保存・JSON保全・復元を通して残ります。
必要なら、期間画面で新しい取得計画を確認してください。
以前の控えは保全したまま、新たに取得できます。

## 保存場所について

保存先は、このブラウザーのこの接続元専用の領域です。
例えばポート4194と4195は別の保存先です。
httpとhttps、別のブラウザー、別のPCも保存先が異なります。

ブラウザーデータを削除した場合や、端末を失った場合は、一覧も失われる可能性があります。
一覧だけを唯一のバックアップにしないでください。
必要な控えはJSONとして別途保存してください。

JSONには公開アドレス・過去の残高・取引履歴が含まれます。
暗号化はされていません。
第三者に渡す場合は、その内容を確認してください。
秘密鍵・シードフレーズ・署名許可を保存する機能はありません。

## JSONとCSVの違い

| 形式 | 内容 | 復元 |
| --- | --- | --- |
| 一覧全体のJSON | 通常・非表示保管を含む全件と元記録 | 一覧に追加できます。 |
| 選択した控えのJSON | 1件の控えと名前・状態・日時 | 一覧に追加できます。 |
| 一覧CSV | 現在の検索条件に合う行の要約 | 復元には使えません。 |
| 従来の期間取得JSON | 期間画面の作業中の控え1件 | 期間画面で開きます。 |

一覧形式のJSONと、従来の個別期間JSONは異なります。
読み込む画面を間違えた場合は、形式の違いを知らせます。

一覧JSONの検査値は、ファイル破損を見つけるためのものです。
作成者や記録の正しさ、第三者監査の完了を証明しません。

## JSONを取り込む

一覧を開いてから、一覧JSONのファイルを選びます。
追加件数・重複件数・非表示保管・再取得が必要な件数を確認します。
確認後に取り込みを実行すると、既存の一覧へ追加されます。

同じ保存番号で内容も同じ場合は重複追加しません。
同じ保存番号なのに内容が違う場合は、全体の取り込みを止めます。
自動で片方を上書きすることはありません。
どちらのJSONも保全して、内容を確認してください。

## 整理と削除

通常の整理には「非表示保管」を使ってください。
保管状態の検索条件を切り替えれば、再び表示できます。
「通常一覧に戻す」で元に戻せます。

完全削除は、非表示保管した控えだけが対象です。
JSONなどで保全してから、対象を確認するチェックを入れて実行します。
別の控えを選ぶと、削除の確認チェックは外れます。
完全削除後は、この画面だけでは戻せません。

## 制限と困ったとき

- 保存数：通常・非表示保管を合わせて12件まで。
- 保存内容：合計48 MiBまで。
- 読み込む一覧JSON：64 MiBまで。
- 保存名：1～60文字。改行・制御文字は使えません。
- 同じ範囲の複数の控えを、勝手に結合しません。
- 保存工程の割合は、残り時間の予測ではありません。

別の画面が先に保存した場合は、一覧を再読み込みしてから操作し直します。
古い画面の内容で、新しい保存を上書きしません。

保存中に中止した場合は、一覧を再読み込みして結果を確認してください。
中止より先に保存が完了していた可能性があります。
「中止したので必ず未保存」とは判断しないでください。

容量不足の場合は、先にJSONを保全して一覧を整理してください。
保存先を読めない場合も、データを自動で消して初期化しません。

## ローカル検証用プレビュー

開発サーバーをテストモードで起動した場合、
次の画面で保存の流れを試せます。

    /test/browser/period-library-demo/

この画面のDAT・EMA・CAWELONはすべて模擬データです。
プレビュー専用の保存先を使います。
実ウォレットへの接続・署名・送金・外部通信を行いません。
