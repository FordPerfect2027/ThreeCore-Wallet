# 複数の保存報告をまとめて確認する

この機能は、PC内に保存済みのDAT・EMA・CAWELONの報告を選び、
複数期間のつながりを調べるためのものです。
元の保存履歴は変更しません。

## 操作の順序

1. ウォレット画面の「複数の報告を、期間で見渡す」を開きます。
2. 「確認用の報告一覧を読み込む」を押します。
3. チェックボックスで1〜12件の報告を選びます。
4. 必要なら確認セットの名前を変更します。
5. 「選択した報告の期間を確認」を押します。
6. 報告名・対象期間・注意点を確認します。
7. 「確認したセットを表示」を押します。
8. DAT・EMA・CAWELONの各カードと「次に確認する箇所」を読みます。
9. 必要に応じてJSON、HTML、CSVをPCに保存します。

チェックした順番は選択内容として保存されます。
期間の検査は、各トークンのブロック番号で並べて行います。
報告の作成日だけで期間の順番を決めることはありません。

## 検索・絞り込み

保存名・メモ・アドレスなどで報告を探せます。
通常の報告、非表示保管の報告、両方を切り替えられます。
計算一致・確認が必要・未完了の状態でも絞り込めます。

絞り込みは表示だけを変えます。
すでにチェックした報告は、画面から隠れても選択に残ります。
「選択○件（絞り込み対象外○件）」で確認してください。
「選択をすべて外す」は、隠れている選択も含めて解除します。
保存済みの報告を削除する操作ではありません。

## 結果の読み方

### 区間を選ぶ一覧

各トークンの期間を、ブロック番号順のボタンで表示します。
区間を押すと、含まれる報告名と、その区間の確認点が表示されます。
抜け区間では、直前・直後にあたる報告が表示されます。
現在選択している区間には枠が付きます。
区間の選択は、保存履歴や確認セットの内容を変更しません。

区間ボタンは同じ幅です。長さの比率を表すグラフではありません。
非常に短い区間が、大きな抜け区間の隣にあっても見落とさないための表示です。
各ボタンに正確な開始・終了ブロックとブロック数を表示します。
色だけでなく、抜け・重複・食い違いを文字でも示します。

Tabで各区間に移動し、EnterまたはSpaceで選択できます。
左右キーは同じトークングループ内の移動、Home/Endは先頭/末尾への移動です。
キーによる移動だけでは、確認結果や区間選択は変わりません。

### 期間境界が一致

同じアカウント・同じチェーンの複数期間について、
前の終了時点と次の開始時点の証拠が一致しています。
各期間の保存された残高とイベントの計算も一致している必要があります。

これは保存済みのデータを照合した結果です。
現在の残高、現在のチェーン状態、データ作成者の正当性を保証しません。
独立したセキュリティ監査の完了を意味しません。

### 計画の抜け

選択した期間の間に、どの計画にも含まれない範囲があります。
抜けを検出しても、その範囲で取引があったと断定しません。
「次に確認する箇所」に範囲と前後の報告名が表示されます。

### 計画の重複

複数の異なる証拠が同じ範囲を含んでいます。
重複区間のブロック数は、重なった分を一度だけ数えます。
トークン数量・イベント・残高を合算する機能ではありません。

### 同じ証拠の重複

別名で保存された報告などに、同じ期間控えの内容が含まれています。
必要なら片方を選択から外して再確認できます。
元の履歴はそのまま残ります。

### 残高やハッシュの食い違い

同じブロック・ハッシュでも保存残高が異なる場合があります。
同じチェーン・ブロックのハッシュが異なる場合もあります。
該当する報告名、ブロック番号、保存された値を確認できます。
片方の値を自動採用したり、元データを書き換えたりはしません。

異なるチェーン同士のハッシュは比較しません。
同一チェーンでは、異なるアカウントやトークンの記録も
同じブロックのハッシュの照合対象になります。
食い違いの原因を、この保存データだけで特定することはできません。

### 取得途中・再取得が必要

計画範囲が存在しても、その全範囲のデータが揃っているとは限りません。
「計画に含まれるブロック数」は、取得済み件数ではありません。
元の報告を開き、取得状況と検証表示を確認してください。

## 確認中に履歴が変わった場合

結果を表示する直前に、選択した報告をもう一度読みます。
名前・メモ・保管状態・証拠などが変わっていた場合は適用を止めます。
一覧を読み直してから、対象を選び直してください。
選択していない報告だけが変わった場合は、適用を続けられます。

結果を表示した後は、その時点の証拠が固定されています。
その後に保存履歴を変更しても、表示済み結果は自動更新されません。
「現在の保存履歴と照合」で、後から生じた違いを確認できます。

照合結果は次の4種類です。

| 表示 | 意味 |
| --- | --- |
| 保存内容と一致 | 同じ保存番号で内容も同じです |
| 名前・メモ・保管状態が変更 | 元の報告は同じで整理情報が変わりました |
| 報告の証拠が変更 | 同じ保存番号の報告内容が異なります |
| 保存番号が見つからない | 現在の保存一覧に同じ番号がありません |

別のブラウザーでJSONを開いた場合、保存番号が見つからないのは正常です。
その結果だけでJSONの証拠を無効と判定しません。

## 保存形式の違い

| 形式 | 用途 | 再読込み | 含む情報 |
| --- | --- | --- | --- |
| JSON | 元の証拠を含む確認セット | 対応 | 全アドレス・残高・イベント・メモなど |
| HTML | 人が読む説明用ファイル | 非対応 | 結果、範囲、確認箇所、選択した報告名 |
| CSV | 表計算ソフトで読む計画範囲一覧 | 非対応 | トークン別の範囲、抜け・重複、確認状態 |

HTML・CSVは、初期状態ではアドレスを短縮し、メモを省略します。
保存名は含まれます。短縮表示は匿名化を保証しません。
JSONには短縮設定・メモ省略設定が適用されません。
どの形式も暗号化されません。

HTMLはスクリプトや外部リソースを含まない単独ファイルです。
CSVでは表計算の数式として解釈される文字列を無効化します。
CSVの範囲は開始を含まず、終了を含む `(開始, 終了]` です。
CSVの `all_arithmetic_agreement` だけで全体の一致を判断せず、
`set_review_required` と `token_continuous` も確認してください。

JSONのSHA-256は、内容の整合性を調べるためのものです。
署名・本人認証・監査証明ではありません。
内容とチェックサムの両方を書き換えた作成者を識別する機能はありません。

## JSONを開く

「確認セットのJSONを選ぶ」でPCのファイルを選びます。
形式とチェックサムを検証し、元の記録から結果を再計算します。
確認画面で適用すると、新しい確認結果が表示されます。
元の報告履歴に追加・上書きすることはありません。
壊れたファイルの場合は、以前の表示結果を保持してエラーを示します。

上限は12報告、正規化した証拠64 MiB、入力ファイル96 MiBです。
JSONの名前や内容にエラーがある場合は、読み込みを拒否します。
処理中は中止できます。中止後に遅れて返った処理結果は適用しません。

## コマンドによる確認

ブラウザーを開かず、PCのファイルを検査することもできます。

```powershell
npm run report-set:check -- "C:\path\ThreeCore-report-set.json"
npm run report-set:check -- "C:\path\ThreeCore-report-set.json" --json
npm run report-set:check -- "C:\path\ThreeCore-report-set.json" --require-continuous
```

終了コード0はファイルの検証成功です。
終了コード1は読み込み・形式・チェックサムなどの失敗です。
終了コード2は、`--require-continuous` 指定時に期間の一致を確認できなかった場合です。
検証成功と、期間がすべて連続していることは別の条件です。
コマンドは元ファイルを書き換えません。
診断出力にはメモ・アドレス・金額の実値を表示しません。

## PC内のプレビュー

```powershell
$env:THREECORE_DEMO_PORT = "4197"
node examples/dev-server.js --ui-test
```

- 通常のウォレット: `http://127.0.0.1:4197/`
- 専用の模擬プレビュー: `http://127.0.0.1:4197/test/browser/report-set-demo/`
- 模擬画面テスト: `http://127.0.0.1:4197/test/browser/`

模擬プレビューの「報告 1・2・3」は連続した期間です。
「期間の抜け」を加えると、抜けの検査を確認できます。
「同じ証拠の再報告」「EMAのハッシュ確認」も選択できます。
非表示保管には「CAWELON取得途中」があります。
全件選択すると、途中の報告の計画が抜けを埋めることがあります。
その場合でも、計画範囲の連続と証拠の取得完了は区別して表示されます。

プレビューは専用のIndexedDBを使用します。
模擬データは通常のウォレットの保存先へ入れません。
接続先ポートが変わると、ブラウザーの保存先も別になります。
持ち運びが必要な確認結果はJSONで保存してください。

## 今回の機能に含まれないもの

送金、署名、トークン承認、交換、資産配分、実チェーンへの自動照会は行いません。
外部サービスとの接続や、AGIとの接続を完成させる機能ではありません。
複数期間・複数トークンの金銭価値や利益を計算する機能でもありません。
GitHubへ反映する操作は、このPC内の開発作業には含まれません。
