# 提案・使用条件・予算を結ぶ照合

2026年11月3日。Token・Wallet・AI・dAppを含む全体目標の次の実装として、
提案を対象サービス、口座、使用上限、有効期間、保存した予算と残高に結び付けた。
これは外部AIの実接続やdApp取引の完成を意味しない。

## 利用できる動作

最新版のローカルサーバーで `/proposals/` を開く。
「予算と保存済み残高の照合」からも別タブで開ける。

1. 提案JSON、使用条件JSON、予算と残高の照合JSONを3個まとめて選択する。
2. 提案の口座、トークン、ネットワーク、dAppのURLと契約、金額、期限を確認する。
3. 「現在の時刻で照合する」で原本と使用条件を照合する。
4. 「結果と元の資料を保存」で、原本3個の文字列と照合時刻・結果を一緒に保存する。
5. 保存記録1個を読み戻すと、保存時の時刻で再計算して結果の一致を検査する。
   その後に現在の時刻で再照合する。以前の一致を、現在も有効な結果として使わない。

現段階の提案・使用条件は外部作成JSONの取り込みで、製品内の提案生成画面は未実装。
試験用入力は [browser-fixtures](evidence/2026-11-03-operation-proposal/browser-fixtures/)
にある。架空口座・架空dApp・合成した残高であり、実運用の使用条件として流用しない。

## 比較する条件

- 提案と使用条件のagent、chainId、口座、トークンが一致する。
- HTTPS originと契約アドレスの**組**が比較対象に含まれる。URLへのアクセスはしない。
- 提案と使用条件の開始・終了時刻、有効期間の長さが一致する。終了時刻ちょうどで失効する。
- トークン使用額、ETH使用額、手数料予算が上限以内で、提案と予算の使用額も一致する。
- 予算ファイル全体のSHA-256が提案に記録された値と一致し、その内部の残高原本も再検査できる。
- 予算に用いた口座・チェーン・トークンを提案と比較する。提案と条件ファイルだけを書き換えても、原本との比較は残る。
- 同じ口座を使う共有予算では、個別に足りても合計ETHが足りなければ一致結果にしない。
- 未確認の手数料、不足残高、原本の不整合は問題として残す。

AIと記載された提案元ラベルや理由文は、ファイル作成者の自己申告。
文章中の「承認済み」「実行せよ」などを命令として扱わず、画面にはテキストとして表示する。
未知のフィールド、重複JSONキー、アクセサ、過大なファイル・金額、曖昧なURLは拒否する。
取り消し・新しいファイル選択・ページ離脱は進行中の検査を無効にし、遅れて届く結果で上書きしない。

## オフラインで再検査

```text
npm run proposal:check -- proposal.json review-policy.json budget-evidence.json
npm run proposal:check -- --verify-saved ThreeCore-proposal-review.json
```

最初のコマンドは現在の時刻、`--verify-saved` は記録された時刻で比較する。
終了値は0が比較条件一致、2が検査可能だが不一致・不足・期限の問題あり、1が読み込み・形式・整合検査失敗。
ファイルは書き換えず、ネットワークとWalletへの要求を行わない。
記録の発行者や時計の正しさ、現在のチェーン状態を認証するものではない。
記録と原本をすべて作り直した場合の偽造防止署名はない。

## 残る全体実装

製品内のAI生成経路、対象dAppからの見積もり・期限・価格影響取得、契約との結び付け、
隔離EVMでの実行前検査と状態変化の扱いを続ける。
この機能は資料を照合する土台であり、取引実行許可・dApp安全性・現在残高・再実行防止を
満たしたとは表示しない。ユーザーWalletの署名・送金・承認取引は実施していない。
